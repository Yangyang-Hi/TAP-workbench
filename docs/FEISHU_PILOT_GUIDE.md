# TAP 预警处置闭环：飞书 Bot 测试操作指引

版本：2026-10-19；目标：同一个 AIME 应用中，1 个真实 ET 风险客户、1 名负责人、1 名运营、1 个测试群。

## 先做什么

可以先创建**企业自建应用并启用机器人能力**。这一工作与代码安装可同时进行。该方案需要应用身份发送消息、交互卡片回调及更新原消息。群中直接配置的自定义 Webhook 机器人不是本包的接入方式。

本包已实现共享事件、动作表单、状态机、真实发送接口、加密回调接收、卡片更新、重试、过程报告和手动真实指标复查。默认 `notification_mode=disabled`，未配置凭证时可以先测试工作台内处置。代码包含真实接口实现，但当前环境没有公司凭证，也没有实际给你、老师或任何群发送消息；不能把本地接口测试当成飞书生产验收。

采用你提供的超头客链路原则：后台发现异常 → 持久化共享台账 → 应用 Bot 通知 → 处理记录入库。双入口处置及卡片同步由本包新增。此次没有重新取得超头客归档包逐文件复核。

## 第一步：创建测试应用、启用 Bot

1. 登录与你们账号所属租户对应的[飞书开放平台](https://open.feishu.cn/app)；如果公司统一使用 Lark 国际版，使用该租户的开放平台，不要混用两个租户的应用与身份。
2. 创建企业自建应用，名称可用 `TAP 风险治理测试`，填写测试用途。
3. 在应用能力中添加或启用“机器人”。
4. 在凭证页面取得应用 `App ID`、`App Secret`。此 App ID 通常以 `cli_` 开头，和 AIME App ID、风神 App ID 完全不同。
5. 在权限管理中申请“以应用的身份发消息” `im:message:send_as_bot`；按平台提示确认更新卡片接口的权限。消息发送/更新文档列出了可满足要求的权限组合，不必为了本次测试一次性申请全部通讯录或聊天记录权限。
6. 将你和老师加入应用可用范围，创建版本并发布或按公司要求提交管理员审批。仅保存开发配置不一定对测试用户生效。
7. 新建只有测试成员的群，将该应用 Bot 加入群。确认加的是刚创建的应用机器人。

如果你没有自建应用权限，需要由企业应用管理员创建或授权。这和当前风神看板权限是两件事。

## 第二步：准备三个身份，不靠名字猜测

| 对象 | 必须得到的值 | 如何使用 |
|---|---|---|
| 你的 AIME 身份 | 当前已验证为 `heyangyang.31`，以实际登录结果为准 | 配置为运营，可查看、分派及复核 |
| 老师的 AIME 身份 | 登录同一个工作台后 `/api/workbench/casework/config` 中的 `actor` | 配置为负责人；也应授予此 AIME 应用访问权限 |
| 两人的飞书身份 | **该 Bot 应用下**的 `open_id`，形如 `ou_...` | 回调操作者映射；不能拿另一个应用的 open_id 直接复用 |
| 测试群 | `chat_id`，形如 `oc_...` | 卡片发送目标；Bot 必须在群内 |

在开放平台 API 调试台使用**此自建应用**调试人员/群标识获取，或请应用管理员提供两个 open_id 和测试群 chat_id。若通过邮箱查询人员标识，需另按该接口要求配置相应通讯录权限和数据范围；本包不要求全量读取通讯录。显示名、邮箱和 AIME username 都不能直接当作 open_id。

## 第三步：将凭证注入 AIME 服务端

在 AIME 当前应用的服务端运行环境中配置以下变量；密钥通过环境变量或 Secret 安全配置录入，不写在前端代码、普通配置 JSON 或聊天消息中。如果应用页面没有此入口，让 AIME 部署侧协助注入同名变量。

| 环境变量 | 填写内容 |
|---|---|
| `TAP_FEISHU_APP_ID` | 上述自建应用的 `cli_...` |
| `TAP_FEISHU_APP_SECRET` | 对应 App Secret |
| `TAP_FEISHU_VERIFICATION_TOKEN` | 应用“事件与回调”中的 Verification Token |
| `TAP_FEISHU_ENCRYPT_KEY` | 同一应用配置的 Encrypt Key；本实现要求加密回调 |
| `TAP_FEISHU_TENANT_KEY` | 当前企业租户 tenant_key；建议填写以额外校验租户 |
| `TAP_FEISHU_REGION` | 中国飞书填 `feishu`，Lark 国际版填 `lark` |
| `TAP_WORKBENCH_URL` | 这个 AIME 应用的实际使用者访问 HTTPS 链接，用于卡片跳转 |
| `AIME_PLUGIN_DATA_DIR` | 沿用 AIME 已设置的持久化数据目录，不改为临时构建目录 |

重启服务使变量生效。工作台事件中的“责任分派与通知 → 集成配置状态”只显示是否已配置，不会把密钥返回前端。

应用通过 `/open-apis/auth/v3/tenant_access_token/internal` 获取并缓存应用 Token；发送走 `POST /open-apis/im/v1/messages`，更新走 `PATCH /open-apis/im/v1/messages/{message_id}`。不需要手动每两小时填一个 Token。

## 第四步：配置两人映射与测试群

修改包内 `config/casework.json`。保留原有 `workflow` 内容，仅替换下面这些字段。尖括号内容是占位说明，必须替换为真实值。

```json
{
  "operators": ["heyangyang.31"],
  "members": [
    {
      "username": "heyangyang.31",
      "display_name": "何扬扬 · 运营",
      "open_id": "<你的该应用open_id>"
    },
    {
      "username": "<老师实际AIME username>",
      "display_name": "测试负责人",
      "open_id": "<老师的该应用open_id>"
    }
  ],
  "test_recipients": [
    {"id": "<测试群chat_id>", "type": "chat_id", "label": "TAP测试群"},
    {"id": "<你的该应用open_id>", "type": "open_id", "label": "我的测试私聊"},
    {"id": "<老师的该应用open_id>", "type": "open_id", "label": "负责人的测试私聊"}
  ],
  "notification_mode": "test"
}
```

`members` 是工作台账号与飞书账号的映射；`test_recipients` 是允许真实发送的目标；`operators` 是能分派和复核的人。三者用途不同。

群成员即使看到卡片，也不会自动获得处理权限。只有已映射且是当前负责人或运营的人，才能在卡片保存处理。默认配置只有你的已知 username，没有猜测老师账号。

首轮仅支持 `disabled` 与 `test`；不要改成 `production`。`test` 只允许向白名单显式点击发送，不会扫描完就自动群发所有客户。

## 第五步：先验证机器回调能进 AIME

在飞书应用“事件与回调 → 回调配置”中，选择将回调发送到开发者服务器，订阅**新版**卡片回传交互 `card.action.trigger`。

填写机器能够访问的真实后端地址：

```text
https://<当前应用后端可被飞书访问的域名>/api/integrations/feishu/card-callback
```

注意：前面的域名需要部署侧确认，不能直接把 AIME 编辑页面的网址拼接成后端接口。`TAP_WORKBENCH_URL` 是给用户点开的页面链接，也不必然是这个机器回调域名。

本包已将这个**唯一回调接口**设为无需浏览器 JWT，但要求飞书签名、Encrypt Key 解密、Verification Token、应用标识、已知发送消息、操作者映射和事件版本校验。其他业务接口仍要求原 AIME 登录鉴权。

飞书保存回调地址时会发送 challenge。本服务通过验证后返回同一 challenge。先确保保存成功，再测试卡片按钮。

若保存失败：

- `302`、SSO 登录页或 HTML：AIME 外层网关拦住机器请求，需要部署侧只对该回调路径配置机器访问；代码里的 Public 不能替代网关设置。
- `401` JSON：检查 Encrypt Key、Verification Token、签名头是否透传、服务器时间是否正确，且订阅的是新版加密回调。
- `404`：域名/后端路径或部署版本不对。
- 超时：检查飞书到该域名的网络、TLS 与服务是否常驻。

若 AIME 无法提供机器可达的 HTTP 入口，需要部署侧提供回调网关，或后续增加官方 SDK 长连接桥接。本包当前实现 **HTTP 加密回调**，没有把尚未实现的长连接标为可用。不要关闭所有 API 的鉴权，也不要为了通过验证把 Bot Secret 填入回调 URL。

## 第六步：按这个顺序跑一条真实链路

1. 两人访问**同一个应用实例**，不要各自安装独立个人实例。确认数据目录持久化。本包共享台账使用该目录下的 `tap_casework.db`，扫描缓存仍沿用原逻辑。
2. 你在风险页跑 ET 真实扫描。原有绝对值规则不改：CCR ≥ 3 且 NFS > 50 进入观察，CCR > 45 进入高风险。缺失值不自动判安全。
3. 完成扫描后的真实命中会自动进入上方“预警处置收件箱”，全量命中保留，Top20 仅影响原扫描表展示。对旧版本缓存结果，可从客户详情点击“打开共享处置”建立事件。
4. 选择**一个**真实命中，记下 `TAP-...` Alert ID。进入“责任分派与通知”，把负责人设为老师的已配置 username，复核人设为你，填写分派说明并保存。
5. 选择测试群或老师的测试私聊，点击“发送测试风险卡片”。看到排队不等于发送成功；等待通知记录为 `sent` 且出现真实 `message_id`。
6. 老师在飞书卡片中选择“接受任务”，填写处理记录，点击保存。飞书显示保存成功后，工作台应在约5秒内看到同一 Alert ID 进入“处理中”，审计来源为 `feishu`。
7. 老师可在同一张更新后的卡片选择“保存处置方案”，选择“客户沟通与整改”，填写沟通对象、整改要求、承诺日期、复查日期和处理记录。未选择动作所需的其他表单项可留空；后端按动作校验必填项。旧版本卡片会被拒绝，须等更新或到工作台刷新。
8. 老师也可在工作台“核查与处置”补充记录。完成实际沟通后填写完成凭证和处理记录，点击“提交完成，等待复核”。事件变为“待复核”，动作完成与沟通完成被记录，风险恢复仍未确认。
9. 你查看同一个事件的操作记录、通知记录和治理效果分析页的过程报告。工作台修改会进入卡片同步队列，更新原消息，不重新群发一张新卡片。
10. 到有足够处置后真实数据时，在“复查与复核”填写独立已结束日期窗口和可比性说明，点击“查询并保存真实复查”。沿用当前点击者 AIME 登录身份查真实 ET/THT 指标；没有缓存用户 JWT 做后台冒名查询。
11. 真实复查达标后，由另一账号复核，填写依据，选择“真实复查达标，风险恢复”再关闭。原报警窗口重叠的 QTD、查询失败、缺 CCR/NFS 或仍超标均不能作为恢复关闭。误报、不适用、有依据的政策例外走相应独立理由，不能混计“风险恢复”。不要为了演示提前把真实客户标为误报。

卡片支持接单、按动作填写和提交完成；分派、审批、复查与关闭由工作台完整表单承接。卡片的“打开工作台”链接携带同一个 Alert ID。

## 处置选项与流转

| 类型 | 选项 | 保存后状态 | 后续 |
|---|---|---|---|
| 客户 | 客户沟通与整改 | 处理中 | 完成凭证 → 待复核 → 独立复查与关闭 |
| 客户 | 继续观察 | 持续观察 | 到期复查，提交凭证后待复核 |
| 客户 | 跨团队核查 | 处理中 | 接收团队、工单与期限明确 |
| 客户 | 发起移除申请 | 待审批 | 另一运营审批 → 处理中 → 保存真实执行凭证 → 待复核 |
| 客户 | 无需进一步处置 | 待复核 | 填写理由证据，由另一账号复核 |
| Quota | 额度核对、额度调整申请、节奏协调、持续监测 | 按配置处理/审批/观察 | 使用独立模板，不套客户教育字段 |

Quota 的模板和状态机已预留；本次自动入账来源是已接通的 ET/THT 客户绝对值命中。**尚未接通真实 Quota 事件生成入口**，也没有从模拟配额数据生成正式预警。

## 12 项验收表

| # | 操作 | 通过标准 |
|---|---|---|
| 1 | 真实 ET 查数 | APPROVE 名单、同期间 CCR/NFS、触发依据可对拍 |
| 2 | 生成事件 | 稳定 Alert ID，保存初始指标/窗口/规则/提报人与工单 |
| 3 | 重复相同窗口扫描 | 同项目、同客户、同提报工单、同指标窗口和规则版本不重复建事件 |
| 4 | 两人看同一实例 | 老师和运营看到同一个授权事件，非相关人不可读 |
| 5 | 显式通知 | `sent` + 真实 `message_id`；不能用预览或排队冒充发送成功 |
| 6 | 飞书接受任务 | 同一事件状态与审计来源更新，不只跳转网页 |
| 7 | 飞书保存动作 | 必填字段缺失被拒绝，完整表单写入同一台账 |
| 8 | 工作台提交完成 | 有完成凭证、进入待复核，不自动标风险恢复 |
| 9 | 原卡片同步 | 工作台修改后原 `message_id` 卡片更新；失败有重试与错误状态 |
| 10 | 并发/重复/旧卡片 | 幂等键不重复计数；旧版本被拒绝，不能覆盖新状态 |
| 11 | 复查与关闭 | 真实独立窗口、达标、另一人复核；未知值不当0；不跨过审批 |
| 12 | 重启及报告 | 重启后事件/审计/通知仍在；动作完成、关闭理由、恢复分别统计 |

## 技术边界与后续接入点

- 共享存储适用于**一个 AIME 实例/一个持久化数据卷**。独立部署、不同数据目录及多副本分散磁盘不会自然共享。多副本上线应将台账迁移到统一数据库，并使用统一任务队列。
- 事件去重键包含项目、客户身份、提报工单、指标起止和规则版本。不同日期窗口会生成不同事件；当前没有定义跨天窗口的连续风险周期合并，需业务确认后再改。
- 同一事件同一测试接收目标的发送请求幂等；2026-10-21 起测试发送失败立即停止，不自动重试；须生成新预览并人工确认重试。应用发送使用稳定 uuid；外部 API 有去重时效，不能宣称跨任意长宕机都能做到绝对只发送一次。失败后可再次点击发送重试，成功消息不会因此重新发一张。
- 更新卡片读取事件最新版本；失败不回滚已保存处置。队列与业务变更同一事务入库。
- 到期日、逾期数量已经记录。**自动复查、逾期升级通知、自动全量群发未开启**；复查需要用户明确点击并使用其当前数据权限。
- 移除/额度调整属于申请记录，不会擅自调用 TAP 权限变更或配额修改接口。执行记录和审批人 SOP 待业务定稿。
- 业务后续主要替换 `config/casework.json` 的模板、人员映射和权限策略。原 `config/data_sources.yaml`、原绝对值阈值与 ET/THT 查询适配器保留。

## 给 AIME 部署侧的具体任务

> 在当前同一个 TAP 应用实例安装本包，保留已有风神取数配置与持久化数据目录。为 Go 服务安全注入上述 TAP_FEISHU_*、TAP_WORKBENCH_URL 环境变量；配置 casework.json 中两人的真实 username/open_id、测试群 chat_id，将通知模式设为 test。只向飞书开放 /api/integrations/feishu/card-callback 的机器回调路由，透传原始 body 和 X-Lark-* 签名请求头，其他业务接口保留 AIME 登录鉴权。确认 HTTP challenge、真实消息发送及卡片按钮回调，再按12项验收验证。Secret 由安全配置输入，不打印、不写入前端、不提交到源码包。若网关不能开放机器回调，明确提供可行的网关/长连接接入方案，不把仅能跳转工作台当成卡片内处理完成。
